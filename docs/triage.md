# 分级是怎么工作的

> 返回 [README](../README.md) · 相关：[知识库](wiki.md) · [部署与排错](deploy.md)

分级回答一个问题：**这条内容值不值得进入你的视野。** 它不做摘要、不做排序，
只做「看不看」的决定。本页展开 README 里没放下的机制细节。

## 自适应投票：逐票评估，证据够就停

默认（`TRIAGE_ADAPTIVE=1`）**不是每条固定判 3 次**，而是每进一张票就重新问一句
「证据够下结论了吗」：

- 第 1 票是**批量调用**——多条内容同一次判出（便宜）；
- **一旦出现 L2/L3 票 → 立即停**：有票说「值得」就不可能再被丢，继续投只是花钱；
- **当前最高是 L1 → 满 2 票停**：L1 是模型「没把握」的聚集区，批内对比效应的摇摆
  大多落在这里。补的那票是**单条独立调用**，且按聚合规则它**杀不掉内容**
  （全票 L0 才判 L0，`[L1,L0]` 平票取高仍是 L1），只可能抬到 L2/L3——
  花一张票修优先级显示，把最易错的判级送去最便宜的复核；
- **至今全是 L0 → 补满票（默认 `TRIAGE_REPEAT=3`）才谈丢弃**：丢弃是唯一不可逆
  动作。哪怕前两张都已 L0，还要投第三张——因为第三张可能就是救回票。

停不停只是省钱判断；停下来的票箱一律交给同一个聚合器裁决
（anti-FOMO 规则，全部偏向「多留」）：

- **全票 L0 才判 L0**；多数 L0 但有分歧 → 抬到至少 L1 保留。
- 有效票少于 2 张**永不判 L0**：唯一 L0 票落该源默认级别（默认本身是 L0 属
  显式「可大量丢」配置，按配置标已读）。
- 非 L0 平票取更高级别。
- LLM 调用失败 → **fail-open**，掉到该源默认级别。
- 补票中途撞上预算闸 → 用已有票聚合（票不足同样不判 L0），剩余留到下一轮。

这些规则写进 prompt 底座与聚合代码，判据配置改不动它们。

为什么要多票不是谨慎，是实测定量结论：

> 同 prompt 连跑两次，20 条里 **6 条（30%）结论相反**，score 完全一致的只有 8/20。
> 原因是批内对比效应——同一条在「一批 10 条」里判会摇摆，拆成单条判就稳定了。
> 所以凡是要动第二票的，补票一律是单条调用。

设置页把自适应关掉（`TRIAGE_ADAPTIVE=0`）回到**不评估、每条投满 repeat 票**；
`TRIAGE_REPEAT`（1–5）调整的是全 L0 情形的满票线。停止条件与聚合分别是
`core.triage.votes_done` / `aggregate_level`，都有单元测试钉住。

## 四层配置，各有边界

| 层       | 内容                                           | 谁维护         |
| -------- | ---------------------------------------------- | -------------- |
| **底座** | 输出格式、四级语义、投票、anti-FOMO、fail-open | 代码，全局唯一 |
| **画像** | 读者是谁、什么对他有价值                       | 你，全局共享   |
| **分类** | 投资 / 技术 / 教育各自的 L0–L3 判据            | 你，每个分类   |
| **本源** | 这个源自己的体裁判据 + 文本结构备注            | 你，每个源     |

冲突时**本源优先**。

画像（`Meta/interest-profile.md`）**只描述读者，不写判据**——它会被拼进每一个源的
prompt。不填也能跑，只是分级少一层
「你是谁」的依据。模板见 `Meta/interest-profile.example.md`。

配置入口：

- 阅读页树上右键分类 / feed → 「配置分级逻辑」（`/triage/config`）
- prompt 预览：`/triage/prompt`

分级 prompt 由规则拼装 + AI 润色生成，**版本落库、不可手工编辑**——每次改动都留
diff 可追溯。配置变动**不重判历史**：历史判定保留当时的理由。

## 为什么不用规则

规则再准也会误杀，而误杀的代价是漏掉重要内容——这正是 FOMO 的根源。

实测：投资人「生活随笔里夹带产业信息」这类条目，规则判不出。判成投资会漏了它是
随笔，判成生活会漏了它有信息。LLM 能同时给出「这是什么」和「对谁有价值」。

## 判定结果怎么呈现

- 树上 `L` 标记 = 该源配了分级判据；**没配判据的源根本不送模型**（徽标为
  「未判定」，零成本），谛听退化成一个普通 RSS 阅读器。
- 列表徽标区分「模型判过 / 失败兜底 / 未判定」，悬停可看判定依据。
- 级别筛选是**多选组合**（`L1+L3`、只看 `L0`），不是阈值式的「L2 及以上」。
- L3 可触发系统通知（macOS / Windows，见 [README 快速开始](../README.md#快速开始)），
  点通知直达那条并展开正文。
- **不做 L3 优先排序**：分级只决定「看不看」，不决定「先看哪个」——排序会引入新的 FOMO。
