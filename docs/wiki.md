# 知识库（wiki）：从划线到属于你的页面

> 返回 [README](../README.md) · 相关：[分级](triage.md) · [部署与排错](deploy.md)

核心哲学一句话：**只有你主动留下的痕迹才叫素材，入库的每一页都要经你亲手审批。**

大多数「AI 知识库」把全文喂进去自动摘要，结果是一堆你没有读过、也不会再看的
「知识」。谛听反过来：正文只当上下文，页面只从你留下的痕迹里长出来。

## 三层素材，信号强度不同

| 素材                           | 是谁的   | 信号含义                                                                                       |
| ------------------------------ | -------- | ---------------------------------------------------------------------------------------------- |
| 文章正文                       | 作者的   | 只作上下文，**不直接提炼**（一段新闻能提十几条「事实」，噪声太大）                             |
| 划线原文                       | 我在意的 | 你选中保存的原文片段，可沉淀事实/观点                                                          |
| 我的原话：提问、划线备注、批注 | 我的判断 | 最高质量信号；进去的不是问题本身，而是问题里露出的判断。预设快捷问题（如「总结这篇文章」）不算 |

分级结果不进 wiki：「模型觉得重要」不是「我在意」。星标是你手动加的，但它管的是整篇留档，
不是可复用的判断，所以同样不进。

## 日常流程

### ① 留痕：划线、批注、问 AI

文章详情、日报、周报三处内容都可以：

- **划线**：选中正文文字即存，可附备注；
- **批注**：对整块内容写你的看法；
- **问 AI**：页头「问AI」按钮唤出浮窗对话（可拖动缩放、流式回复），
  带着当前文章上下文提问；**AI 的回复也可以再划线**。

痕迹都存在谛听自己的 SQLite 里，挂在来源上（文章 / 日报 / 对话），不动 Miniflux。

### ② 编译成草稿：一枚按钮，提炼+编译一条龙，必须人点

`/wiki` 首页点「**编译成草稿**」——名字叫编译，实际把新痕迹先提炼成**候选**、
再编译成**草稿**，一次点完：

- 沉淀是**你主导**的事，所以**绝不自动触发**：不挂在「保存划线」「发完消息」这类
  高频动作上，只有你按下按钮才开工；
- **候选是原子的**：一条候选 = 一个能脱离上下文独立读懂的判断点，不是一篇文章的
  摘要；编译时按「原子概念」分组，一组编译成一张页；
- 每条候选的引文（quote）必须**逐字对上你留下的痕迹**（你的原话或你划的原文）
  ——程序守卫，对不上就丢弃并显示丢弃条数，防止模型编造「你说过的话」；
- 提炼出 0 条是合法结果：没有值得沉淀的，就不沉淀；
- 候选可在 `/wiki/candidates` 只读翻阅、丢弃、改判（这个页不花钱）。

### ③ 审批：入库前的唯一闸门

草稿在**审批浮层**（`/wiki/approval`）里裁决，整批确认后才入库：

- 标题直改（**slug 跟随标题**，中文自动转拼音）、标签就地改；
- **审批对话**：和 agent 讨论这份草稿，它可以读草稿、改字段、润色结论、并入已有页；
- **重编结论**：一键让模型基于候选重写结论段；
- **找找相关页**：LLM 推荐可能相关的已入库页，一键改判为「并入」而不是新建；
- 逐份标记已审批 / 未审批，最后一键**整批入库**。

### ④ 入库：纯 Markdown 文件，可被 Obsidian / git 接管

入库页落盘为 `wiki/<领域>/<slug>.md`，附 `index.md`、`log.md`、`meta/`、
`sources.json`（页面 → 来源反向映射）。默认在 `data/wiki/`，`.env` 的 `WIKI_DIR`
可直接指向你的 Obsidian vault。

浏览入口：`/wiki`（按标签 / 来源筛选）、`/wiki/tags`（全库词表）、
`/wiki/page?p=…`（单页详情）。

已入库页不是终点：可以「拉入审批编辑」（生成替换稿，走同一套审批后覆盖）、
「请求删除」（同样走审批，候选逐条决定去向）。改标题、删页产生的断链会列出来，
由你逐条改指向或降级。

### ⑤ 本体：领域是受控枚举

`Meta/ontology.md` 里的「领域」表是 domain 的**唯一真值**——草稿只能落进表里
列出的领域。在设置页 `/prefs` 整篇在线编辑；模板见 `Meta/ontology.example.md`。

## 钱与锁：可预期的行为

- **独立预算池**：对话 / 提炼 / 编译 / lint 共池，默认 **¥0.5/天**
  （`WIKI_BUDGET_CNY`，`/costs` 可调）。超限不是静默失败：对话与编译被拒绝并
  明确提示，次日恢复。
- **编译中**：按钮可见地灰掉，显示已跑时长；进程意外被杀后锁会放行，但明说
  「上次没跑完」。
- **待审批草稿会阻塞新一轮提炼 + 编译**：先把手上的草稿裁决完，才能开新批——
  防止草稿越积越多、审批变成欠债。反向也锁：编译中审批 / 编辑按钮同样灰掉。

## 相关配置（`.env`）

| 键                         | 默认        | 说明                                           |
| -------------------------- | ----------- | ---------------------------------------------- |
| `WIKI_DIR`                 | `data/wiki` | 落盘根目录，可指向 Obsidian vault              |
| `WIKI_BUDGET_CNY`          | `0.5`       | 知识库池日上限（¥）                            |
| `WIKI_CHAT_ENABLED`        | `1`         | 问 AI 对话开关                                 |
| `WIKI_CHAT_ARTICLE_CHARS`  | `6000`      | 正文进 prompt 的字数上限（每轮重发，越大越贵） |
| `WIKI_CHAT_HISTORY`        | `6`         | 带多少条历史消息进上下文                       |
| `WIKI_CHAT_MAX_TOKENS`     | `3072`      | 单轮输出预算                                   |
| `WIKI_CHAT_QUESTION_CHARS` | `2000`      | 单条提问长度上限                               |
